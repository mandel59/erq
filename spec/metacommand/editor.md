# .editor メタコマンド

## 概要
`.editor` は TTY 上の対話セッション専用のドットメタコマンドで、Node.js REPL の editor モードに似た入力モードへ切り替えます。プロンプトを非表示にしたまま、生のテキストを複数行まとめて記述し、意図したタイミングで評価できます。子プロセス側での実装は行わず、親プロセス (`src/parent.js`) がローカルで処理します。

## 構文
```text
.editor
```

- 引数は受け付けません。追加のトークンを渡すと `usage: .editor` が表示されます。

## 前提条件
- `stdin` と `stderr` の両方が TTY のときのみ有効です。パイプやリダイレクト経由で実行している場合は `.editor is only available when stdin is a TTY` が表示され、モード移行は行われません。
- 既に editor モード中、または読みかけのステートメントがある状態で `.editor` を実行すると、現在の入力を終えてから再試行するよう促されます。

## 挙動
1. editor モードに入ると、プロンプト表示を停止し、利用者が入力した各行をそのまま内部バッファに蓄えます。
2. `Ctrl+D` を押すと入力完了とみなし、バッファ内容の末尾に改行と `;;` を補ったうえで既存のクエリ処理系に渡して評価します。結果は通常の対話入力と同じく即時に表示されます。
3. `Ctrl+C` を押すと editor モードはキャンセルされ、蓄積済みのバッファは破棄されます。メインプロンプトに復帰します。
4. エディターモード中は補完やヒストリ移動など Readline の通常操作を無効にし、記述中のテキストが勝手に整形されないようにしています。
5. 子プロセスへ `.editor` コマンドが渡ることは想定していませんが、万一到達した場合は `.editor is only available in interactive mode` というエラーで即座に失敗します。

これにより、SQL/Erq スクリプトを一時的に集中して書き込み、完成したものだけを実行するワークフローを対話環境から手軽に行えます。
