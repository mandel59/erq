# CLI エントリポイント構文

Erq のエントリポイントは、以下の 4 つの規則を軸に組み立てられています。ここでは Peggy 実装ではなく、一般的な EBNF 表記で振る舞いを記述します。

| 規則 | 説明 |
| --- | --- |
| `start` | 1 文を解析する基本の開始規則。 |
| `cli_readline` | REPL が 1 行入力を解釈する際に使用。 |
| `script` | `.erq` ファイル全体を読み込むための規則。 |
| `CLICommand` | ドットメタコマンドの行を処理。 |

## `start`

```ebnf
start ::= WS Statement WS
```

先頭と末尾の空白を無視しながら、単一の `Statement` を解析します。CLI 以外に API からの評価にも利用されます。

## `cli_readline`

```ebnf
cli_readline ::= CLICommand
               | WS (Statement? WS ";;" WS)* Statement? WS
```

- 行頭が `.` のときは `CLICommand` とみなします。
- それ以外は `;;` 区切りでステートメント列を読み取ります。空ステートメント（`;` だけの入力）は無視されます。

REPL では、上記のルールを使って「まだ構文が完結していないか」を判断します。

## `script`

```ebnf
script ::= WS (Statement WS ";;" WS)* Statement? WS
```

複数行のスクリプトを読み込み、`;;` をステートメント区切りとして扱います。最終行の `;;` は省略可能です。

## `CLICommand`

```ebnf
CLICommand ::= "." Identifier CLIArgumentList?
CLIArgumentList ::= WS CLIArgument (WS CLIArgument)*
```

- `Identifier` は英数字と `_` のみで構成され、空文字も許容します（`.quit` や `.help` など）。
- 引数は空白で区切ります。シェルの引数と似て、シングルクォートは文字列をそのまま保持し、ダブルクォートはバックスラッシュをエスケープ文字として解釈します。クォートされていない文字列は空白やクォート文字に遭遇するまで読み取ります。
- 解析結果はコマンド名と引数リストに整理され、ドットメタコマンドのディスパッチに渡されます。

## 空白とコメント

`WS` は空白文字やコメント（`-- ...`、`/* ... */`）をまとめて表すための記号です。すべての上位規則で `WS` を挿入し、入力に含まれる余分な空白を透過的に扱います。
