# 課題: CLIでの貼り付け入力が破損する

## 概要
- `bin/erq-cli.js` で起動するREPLに複数行をペーストすると、VS Code 統合ターミナルなど一部TTYで行頭が壊れたり `SyntaxError` になる。
- `readline` の `line` イベント処理が終わる前に `rl.prompt()` が再描画を行い、端末側が送り続けているクリップボード文字列を上書きしてしまう。

## 再現手順
1. VS Code の統合ターミナルで `erq` を実行し、`erq>` プロンプトを表示する。
2. `examples/subquery.erq` の内容を一括コピー＆ペーストする。
3. 途中で `...>` 行に乱れた文字列が入り、最後のクエリで `SyntaxError` が発生する。

## 期待される挙動
- 端末が複数行をバースト送信しても、受信した順に安全にバッファリングし、すべての行を評価した後で一度だけプロンプトが描画される。

## 実際の挙動
- `client.runSqls` の実行が完了するたびに即 `rl.prompt()` が呼ばれていたため、処理中に流入していたペースト文字列をカーソル頭出しで上書きし、入力が壊れていた。

## 根本原因
- `rl.on("line", async ...)` を利用した並行処理では、`await client.runSqls` 中にも次の `line` イベントが届く。
- 先頭の処理が完了するたびに `rl.prompt()` が同期的に呼び出され、TTY のバースト入力よりも先に描画を走らせてしまう。
- 本質的には「プロンプト描画と貼り付けデータの受信が競合し、ターミナルバッファが破壊される」ことが原因。

## 修正タスク
- [x] `src/parent.js` を `for await...of` ベースの逐次処理へ刷新し、`SerialAsyncTaskQueue` を除去する。
- [x] プロンプト描画を遅延させ、連続入力中は `rl.prompt()` を呼ばないよう `setTimeout` ベースのスケジューラを導入する。
- [x] 連続貼り付けで問題が再現しないことを、VS Code 統合ターミナルなどで手動確認する。

## 補足
- 追加の自動テストは環境依存（TTY動作）で再現しづらいが、AVAの既存CLI系テストをすべて通し、回帰が無いことを確認している。
