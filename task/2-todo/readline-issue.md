# 課題: CLIでのペースト/IME入力が欠落する

## 概要
- `bin/erq-cli.js` 経由で起動する対話CLIで、Node.jsの`readline`モジュールを利用している。
- 連続貼り付けやIME確定のように短時間で複数の `line` イベントが届くと、2行目以降が評価されずプロンプトが返らなくなる。
- この状態では利用者は再度改行を送るまで結果が得られない／最悪入力が失われたように見える。

## 再現手順
1. `node ./bin/erq-cli.js` を起動し、`erq>` プロンプトを表示させる。
2. 以下の2行をまとめてペーストする（もしくはIME学習済みの長文を一括確定する）。
   ```sql
   select 1;
   select 2;
   ```
3. 1行目だけが実行され、2行目は結果が返らずプロンプトも点滅したままになる。さらにEnterを押すと2行目がようやく処理される。

## 期待される挙動
- `readline` が受け取った行は入力順にすべて評価され、追加のEnterを押さなくても即座に `client.runSqls` に渡されること。

## 実際の挙動
- 最初の `line` イベント処理中に `state` が `"eval"` のままになり、同期間に到着した追加行は `state === "read"` 条件に弾かれて評価されない。
- 利用者が再度Enterを押して `state` が `"read"` に戻るまで、バッファに溜まった入力が取り出されない。

## 根本原因
- `src/parent.js:216-242` にある `rl.on("line", async ...)` は `state === "read"` のときだけ `parseErq` / `client.runSqls` を実行するガードを設けている。
- `async` リスナーは `await client.runSqls` の間に並行して呼ばれるため、2本目の `line` が `state === "eval"` を検知して即 return する。
- 2本目以降の `line` は `input += line + "\n"` までは行うが、評価ループに再投入されないため、貼り付けやIME確定のような連続入力が無視される。

## 修正タスク
- [ ] `src/parent.js` で `line` イベントを逐次キューイングする仕組みを追加し、`client.runSqls` の完了後に残りの入力を必ず再評価する。（例: `state === "eval"` 時はキューに積み、処理完了時に drain する）
- [ ] 連続 `line` をシミュレートするユニット/統合テストを追加し、複数行の貼り付けやIME確定が順序通り処理されることを検証する。
- [ ] ドキュメントまたはCHANGELOGに、本不具合の修正内容と影響範囲（CLIのインタラクティブ入力）を追記する。

## 補足
- `state` フラグをUIロジックにも使っているため、評価キュー追加時は `handleSigint` / `handleSigtstp` での遷移も同時に見直すと安全。
